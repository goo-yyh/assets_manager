## 1. 项目概述

### 1.1 项目背景

随着震裕科技规模扩大和智能制造推进，集团对固定资产管理提出更高要求。现有管理方式存在资产台账不清、设备档案缺失、维修保养信息分散、备品备件管理混乱、跨厂区调拨流程不规范等问题，影响资产利用效率和运营管理水平。

### 1.2 项目目标

建设集团级固定资产数字化管理平台，从资产转固入账开始，覆盖资产使用、调拨、维修保养数据展示、出售、报废处置等全生命周期管理，并与 MOM、财务、项目管理等现有系统对接，为管理层提供资产数据支撑和决策依据。

### 1.3 建设原则

- 实用性：以业务需求为导向，功能贴合实际管理场景。
- 扩展性：采用模块化架构，支持后续功能扩展与系统对接。
- 易用性：提供友好操作界面，降低用户学习成本。
- 安全性：具备权限控制、数据加密、审计追溯等安全机制。
- 集成性：预留标准接口，支持与 MOM、财务、项目管理、ERP 等系统对接。

## 2. 建设范围与边界

### 2.1 系统管理范围

系统管理起点为“资产转固入账”。设备验收合格并正式转为固定资产后，资产信息从财务系统或项目管理系统同步进入本系统，开始进入资产全生命周期管理。

系统覆盖范围包括：

- 转固入账
- 日常使用
- 调拨转移
- 维修保养数据展示
- 出售/报废处置
- 盘点管理
- 数据分析与可视化看板

### 2.2 系统边界外

以下业务由客户既有系统负责，本系统不重复建设：

- 项目立项、预算审批：由项目管理系统负责。
- 采购申请、供应商选择、采购执行：由采购系统负责。
- 到货验收、安装调试：由项目管理系统或采购系统负责。
- 在建工程管理：由财务系统负责。
- 维修保养业务操作：由 MOM 系统负责。

## 3. 一期核心需求

一期聚焦核心资产管理能力快速上线，范围包括：

- 集团级统一资产台账与编码标准化
- 设备档案管理，即“一机一档”
- 资产转固后的全生命周期管理
- 集团多厂区资产管理与跨厂区调拨
- MOM 系统数据对接与关联展示
- 财务系统对接
- 数据分析与可视化看板

后续阶段可扩展备品备件管理、移动端 APP、扫码硬件集成、大屏看板定制、AI 智能分析等能力。

## 4. 角色与权限

系统应至少支持以下角色，具体权限矩阵在详细设计阶段确认：

- 资产管理员：维护资产台账、资产分类、盘点计划、调拨和处置流程。
- 设备档案管理员：维护设备档案、技术参数、证件、图片和变更记录。
- 财务人员：查看财务编号、资产原值、折旧、净值和处置核销状态。
- 厂区/部门负责人：发起或审批调拨、处置、盘点差异等业务。
- 管理层：查看资产总览、厂区对比、费用分析和预警看板。
- 系统管理员：维护组织、用户、角色、菜单、按钮和数据权限。

## 5. 功能需求

### 5.1 固定资产台账管理

#### 5.1.1 功能说明

建立集团级统一固定资产台账，对每项资产生成唯一编码，记录资产基本信息、所属厂区/车间/产线、当前状态、关联财务编号等核心信息。

#### 5.1.2 关键需求

- 支持接收转固资产数据并建立资产台账卡片。
- 支持自动生成唯一资产编码，编码应支持二维码或条形码扩展。
- 支持按设备类型、用途等维度进行资产分类管理。
- 支持按资产名称、编码、所属厂区、状态等条件组合查询。
- 支持模糊搜索与筛选。
- 支持 Excel 批量导入存量资产数据。
- 支持资产与财务固定资产编号一一绑定。
- 支持资产地图或可视化方式展示资产在各厂区的分布情况。
- 支持定期盘点计划、扫码盘点和盘点差异处理。

### 5.2 资产全生命周期管理

#### 5.2.1 功能说明

覆盖固定资产从转固入账到出售/报废处置的全过程管理，每个环节保留审批记录和追溯记录。

#### 5.2.2 流程节点

- 转固入账：接收转固数据，建立资产台账并关联财务编号。
- 日常使用：跟踪资产状态，管理领用与归还记录。
- 调拨转移：支持跨部门、跨厂区调拨申请与审批。
- 维修保养：从 MOM 系统获取维保数据并在资产台账或设备档案中展示。
- 资产处置：完成出售/报废申请、审批与财务核销。

#### 5.2.3 关键需求

- 支持从项目管理系统、财务系统接收资产转固信息。
- 如无项目管理系统，支持手工录入或 Excel 导入转固信息。
- 支持配置转固、调拨、处置等业务审批流程。
- 支持出售/报废申请，记录处置原因、评估信息、审批信息和核销结果。
- 资产处置后应更新资产状态，并保留历史记录用于追溯。

### 5.3 设备档案管理

#### 5.3.1 功能说明

为每台设备建立完整的“一机一档”，汇集设备从采购到退役的资料。

#### 5.3.2 档案内容

- 基本信息：设备名称、型号、编码、厂家、购置日期、原值。
- 技术参数：设备规格、性能参数、技术指标。
- 验收资料：验收报告、调试记录、试运行报告。
- 合同证件：采购合同、技术协议、保修条款、年检证书。
- 图片影像：设备照片、铭牌照片、安装位置图。
- 变更记录：设备改造、升级、参数变更历史。

#### 5.3.3 关键需求

- 支持按资产编码关联设备档案。
- 支持附件上传、查看和下载。
- 支持设备档案变更记录留痕。
- 支持在资产台账中快速查看设备档案。

### 5.4 维修保养数据展示

#### 5.4.1 功能说明

设备维修保养业务操作由客户现有 MOM 系统负责。本系统从 MOM 系统获取维修保养数据，在资产台账和设备档案中关联展示，便于资产管理人员了解设备维保历史和当前状态。

#### 5.4.2 关键需求

- 展示设备实时运行状态：运行、停机、故障。
- 展示设备 OEE，即综合设备效率数据。
- 展示维修记录，包括故障原因、维修方案、维修费用等。
- 展示保养记录，包括保养内容、保养时间、更换备件等。
- 展示故障告警信息。
- 系统不重复建设 MOM 的维修保养业务操作功能。

### 5.5 集团多厂区管理

#### 5.5.1 功能说明

支持集团级多工厂、多厂区资产统一管理，实现资产跨厂区查看、调拨和归属调整，优化集团整体资产配置。

#### 5.5.2 关键需求

- 支持按集团、厂区、车间、产线等组织层级管理资产。
- 支持跨厂区资产查询和统计。
- 支持跨厂区调拨申请、审批和执行。
- 支持调拨后自动更新资产归属。
- 支持财务系统同步调整资产归属。
- 支持设备档案随资产一同转移。

### 5.6 数据分析与可视化看板

#### 5.6.1 功能说明

提供多维度资产数据分析与可视化展示，支撑管理决策。

#### 5.6.2 看板内容

- 资产总览：资产总数、总价值、分类统计、状态分布。
- 厂区对比：各厂区资产数量、价值、利用率对比。
- 维修分析：故障率趋势、维修费用。
- 费用分析：资产折旧趋势、费用汇总。
- 预警看板：年检到期、资产异常预警。

## 6. 系统集成需求

### 6.1 MOM 系统对接

#### 6.1.1 对接目标

客户 MOM 系统负责设备维修保养、运行状态监控和数据采集。本系统一期对接 MOM 数据，并在资产台账中关联展示。

#### 6.1.2 对接数据

- 设备运行状态：运行、停机、故障。
- 设备 OEE：综合设备效率。
- 维修记录：故障原因、维修方案、维修费用等。
- 保养记录：保养内容、保养时间、更换备件等。
- 故障告警信息。

#### 6.1.3 对接方式

- 支持通过 RESTful API 实时同步。
- 支持通过消息队列 MQ 异步推送。
- 具体接口字段、同步频率、鉴权方式和异常重试机制由双方技术团队确认。

### 6.2 财务系统对接

#### 6.2.1 对接目标

实现资产台账与财务固定资产管理数据一致，支撑资产价值查询、价值变动同步和处置核销。

#### 6.2.2 对接内容

- 固定资产编码关联：资产台账与财务固定资产编号一一对应。
- 转固数据同步：从财务系统接收新增固定资产信息。
- 价值变动同步：折旧、增减值等变动实时或定期同步。
- 处置核销：资产报废或出售时同步财务核销。
- 价值查询：查询资产原值、累计折旧、净值。

### 6.3 项目管理系统对接

#### 6.3.1 对接目标

如客户已有项目管理系统，可接收项目竣工验收信息，并自动触发资产入账。

#### 6.3.2 处理方式

- 有项目管理系统：接收项目竣工验收信息，自动生成待入账资产数据。
- 无项目管理系统：通过手工录入或 Excel 导入转固信息。

## 7. 非功能需求

### 7.1 安全需求

- 用户认证：JWT Token + 刷新机制，支持多端登录。
- 权限控制：采用 RBAC 角色权限模型，支持菜单、按钮、数据三级权限。
- 数据安全：敏感数据加密存储，传输层采用 HTTPS 加密。
- 操作审计：关键操作记录日志，支持审计追溯。
- 接口安全：接口签名验证，防重放攻击。

### 7.2 性能需求

- 系统常规操作响应时间应小于 2 秒。
- 系统应支持 500 并发用户。
- 数据查询、统计看板、批量导入等高耗时场景需在详细设计阶段定义性能指标和异步处理策略。

### 7.3 质量需求

- 遵循企业级编码规范。
- 建立代码评审机制。
- 单元测试覆盖率目标大于 60%。
- 集成测试覆盖主要业务流程与系统接口。

### 7.4 易用性需求

- 界面应符合资产管理业务人员日常操作习惯。
- 高频操作应减少输入步骤，支持搜索、筛选、批量导入等效率工具。
- 关键流程应提供明确状态、审批记录和处理结果。

### 7.5 可扩展性需求

- 系统采用模块化架构，便于后续扩展备品备件、移动端 APP、扫码硬件、大屏看板、AI 分析等功能。
- 接口层应预留与 MES、ERP、财务、项目管理等系统对接能力。

## 8. 技术方案约束

### 8.1 技术栈

- 后端：Spring Boot 3.x + Java 17+
- 前端：Vue 3 + Element Plus
- 数据库：MySQL 8.0
- 缓存：Redis 7.x
- 消息队列：RabbitMQ
- 文件存储：MinIO
- 报表与可视化：ECharts
- 接口文档：Swagger / Knife4j
- 权限框架：Spring Security + JWT
- 工作流：Flowable

### 8.2 部署要求

- 生产环境最低配置：4 核 8G 以上。
- 数据库建议配置：8 核 16G。

## 12. 验收标准

### 12.1 功能验收

- 完成一期范围内资产台账、设备档案、生命周期、多厂区、系统对接、数据看板等核心功能。
- 关键业务流程可完整闭环，包括转固入账、调拨、处置、盘点和维保数据展示。
- 与 MOM 系统、财务系统完成联调，接口数据可正确同步或展示。

### 12.2 性能验收

- 常规页面和接口响应时间满足小于 2 秒的目标。
- 通过 500 并发用户的压力测试或等效容量验证。

### 12.3 安全验收

- 用户认证、角色权限、菜单权限、按钮权限、数据权限生效。
- 敏感数据传输使用 HTTPS。
- 关键操作日志可查询、可追溯。
- 对外接口具备鉴权或签名校验机制。

### 12.4 文档验收

- 需求文档、设计文档、接口文档、操作手册、部署文档齐备。
- 接口文档与实际接口保持一致。
- 用户可依据操作手册完成核心业务操作。
