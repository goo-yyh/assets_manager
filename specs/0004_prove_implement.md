# 资产管理系统 Demo 功能完整性与交互优化实施文档

> 依据：`specs/0002_demand_prove.md`、当前前端实现。  
> 目标：在现有静态 Demo 基础上补齐一期需求展示、完善表格操作闭环、优化菜单层级和滚动布局。

## 1. 优化目标

本次优化不改变技术栈，继续使用 React、TypeScript、Vite、Ant Design、ProComponents、React Router、TanStack Query、Zustand、Axios、Zod、ECharts。

优化后必须达到以下效果：

- `FR-001` 至 `FR-060` 在页面、数据、交互或看板中均有明确展示入口。
- 所有按钮点击后都有可见结果：打开详情、打开表单、改变表格数据、生成关联记录、更新状态或给出明确业务提示。
- 新增、编辑、删除、审批、同步、调拨、处置、入库、出库、盘点等操作必须实时反映到对应表格。
- 表单字段严格来源于当前表格列和业务字段，不再使用统一的“业务标题、责任人、业务原因”泛化表单。
- 页面只允许内容区滚动；表格只在列宽确实超过容器时产生横向滚动，不出现无意义的双滚动条。
- 菜单按业务域拆成二级分组，避免多个不同业务堆在同一页面或同一层级。

### 2.2 当前主要问题

- `src/api/mockAdapter.ts` 对所有非 GET 请求只返回“操作已模拟提交”，没有改变 mock 数据。
- `src/pages/Management/ManagementPage.tsx` 使用统一操作表单，字段无法匹配不同表格列。
- `PageAction` 没有携带当前行记录，表格内的编辑、审批、调拨、处置无法基于行数据处理。
- 维修保养、系统集成、设备档案详情内容集中在单页，信息密度过高。
- `/scope` 是孤立一级菜单，与组织架构、资产地图、厂区对比存在重复。
- 部分表格固定 `scroll.x`，在内容不足时也会出现横向滚动条。

## 4. Mock 写操作改造

### 4.1 数据存储方案

新增 `src/mock/store.ts`，将当前静态数组初始化为可变数据集。

实现规则：

- 首次进入 Demo 时，从 `src/mock` 静态数据克隆到 `localStorage`。
- 每个数据集使用独立 key，例如 `asset:list`、`asset:transfer`、`spare:stock`、`system:users`。
- 所有列表查询从 store 读取，不直接读取静态数组。
- 所有写操作更新 store 后返回最新记录。
- 提供“重置演示数据”能力，清空 localStorage 并重新加载初始 mock 数据。

建议结构：

```txt
src/mock/
  store.ts
  actionHandlers/
    assetActions.ts
    equipmentActions.ts
    spareActions.ts
    integrationActions.ts
    systemActions.ts
```

### 4.2 API 约定

新增通用写接口，替代当前只返回成功的 `/action`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/mock/:resource` | 新增记录 |
| `PATCH` | `/mock/:resource/:id` | 编辑记录 |
| `DELETE` | `/mock/:resource/:id` | 删除记录 |
| `POST` | `/mock/:resource/:id/actions/:actionKey` | 行内业务操作 |

响应必须包含：

```ts
type MutationResult<T> = {
  record?: T;
  affected?: Array<{ resource: string; id: string }>;
  message: string;
};
```

前端 mutation 成功后必须：

- 更新当前列表 query cache。
- 对受影响资源执行 `invalidateQueries`。
- 显示成功消息。
- 如果新增记录属于当前筛选范围，立即展示在表格首行。

### 4.3 表单生成规则

每个页面配置新增 `formFields`，不能再用统一表单。

字段来源优先级：

1. 当前表格列 `columns`。
2. 业务必需但不展示的字段，例如 `factoryId`、`id`、`createdAt`、`status`。
3. 当前行数据默认值。

字段类型映射：

| 列类型 | 表单控件 |
| --- | --- |
| `text` | `ProFormText` |
| `status` | `ProFormSelect` |
| `money` | `ProFormDigit` |
| `number` | `ProFormDigit` |
| `percent` | `ProFormDigit` |
| `list` | `ProFormSelect` 或 `ProFormCheckbox.Group` |
| 长文本字段 | `ProFormTextArea` |
| 日期字段 | `ProFormDatePicker` |
| 文件资料 | `Upload` 演示控件 |

Zod schema 按页面拆分到 `src/validators`，新增、编辑、审批、业务操作各自有独立校验。

### 5.1 `ManagementPage` 拆分

当前 `ManagementPage` 继续作为轻量列表页基础，但要拆出以下组件，避免单文件过长：

```txt
src/pages/Management/components/

src/pages/Management/hooks/

  useActionColumnWidth.ts
```

### 5.2 Action 上下文

新增类型：

```ts
type ActionContext = {
  action: PageAction;
  row?: RowRecord;
};
```

行内操作必须传入 `row`：

- 详情：打开详情抽屉。
- 编辑：以当前行作为表单初始值。
- 删除：弹出确认框，确认后删除当前行。
- 审批：打开审批表单，提交后更新当前行状态。
- 业务动作：根据当前行生成关联记录或更新状态。

### 5.3 按钮规范

每个可维护表格至少包含：

- `详情`
- `编辑`，有编辑权限时展示
- `删除`，有编辑权限且业务允许删除时展示
- 当前业务动作，例如 `调拨`、`处置`、`审批`、`入库`、`出库`、`盘点`

只读页面只能包含 `详情`、`关联资产`、`关联档案`、`查看记录` 等真实可见操作，不能出现点击无结果的按钮。

| 日常使用 | 领用/归还 | 更新资产使用状态、使用部门、责任人，生成历史追溯记录。 |

## 7. 数据联动规则

必须实现以下跨表联动：

- 资产入账完成：`assetIntakeRecords` 更新，`assets` 新增，`equipmentFiles` 新增，`operationLogs` 新增。
- 资产调拨执行：`assetTransferRecords` 更新，`assets` 厂区字段更新，`equipmentFiles` 厂区字段更新，`syncRecords` 新增财务同步记录。
- 资产处置核销：`assetDisposalRecords` 更新，`assets.status` 改为 `disposed`，`syncRecords` 新增核销记录。
- 资产盘点完成：`assetInventoryPlans` 更新，差异记录进入 `operationLogs` 或历史追溯数据集。
- 备件入库完成：`spareInboundRecords` 更新，`spareParts.stockQty` 增加，库存状态重算。
- 备件出库完成：`spareOutboundRecords` 更新，`spareParts.stockQty` 减少，库存状态重算。
- 备件退库完成：新增退库入库单，`spareParts.stockQty` 增加。
- 备件盘点完成：`spareInventoryPlans` 更新，按差异调整库存。
- 附件上传：`attachmentRows` 新增，同时更新对应 `equipmentFiles` 内部文档数组和完整度。
- 角色权限更新：`roleRows` 更新，当前用户如果属于该角色，需要刷新菜单和按钮权限。

库存状态重算规则：

```txt
stockQty < minStock       -> low_stock
stockQty > safetyStock*2  -> over_stock
lastUsedAt 超过 180 天    -> inactive
其他                      -> normal
```

## 8. 布局与滚动优化

### 8.1 页面滚动规则

- `body` 保持 `overflow: hidden`。
- 只允许 `.app-content-scroll` 产生纵向滚动。
- `ProLayout` 的侧边栏、顶部栏固定，不参与内容滚动。
- 页面内 Card、Table、Chart 不单独设置不必要的 `height: 100vh`。

### 8.2 表格滚动规则

- `scroll.x` 只在列宽总和大于容器宽度时设置。
- 操作列固定右侧，宽度由按钮数量和短文案动态计算。
- 表格列超过容器时允许横向滚动，但不能导致页面整体横向滚动。
- 弹窗、抽屉内表格使用局部滚动，宽度不超过弹层内容区。

### 8.3 内容密度规则

- 同一页面最多承载一个主表格和两个辅助区块。
- 维修保养、系统集成这种多表格页面拆成独立子页面。
- 图表页面使用筛选区、统计卡片、图表、明细抽屉的结构，避免图表和大表格同时挤在首屏。
- 空数据必须展示业务化空状态和可执行动作，例如“暂无入库单，点击新增入库”。

## 10. 验收清单

### 10.1 需求完整性

- `FR-001` 至 `FR-060` 均能在路由、页面、操作或看板中找到对应展示。
- 一期范围包含备品备件完整管理，不再只作为二期或展示项。
- MOM 数据只展示，不提供本系统内维修保养写操作。
- 财务、项目、MOM 对接均有同步状态、同步记录和字段映射。

### 10.2 操作闭环

- 每个新增操作提交后，当前表格能立即看到新增记录。
- 每个编辑操作提交后，当前行字段立即更新。
- 每个删除操作确认后，当前行从表格中移除。
- 审批、调拨、处置、入库、出库、退库、盘点、同步等业务动作会更新状态并生成关联记录。
- 所有只读操作至少打开详情抽屉、跳转关联页面或更新筛选条件。

### 10.3 权限与数据范围

- 不同角色菜单不同。
- 无权限路由进入 `/403`。
- 无权限按钮不可见或不可点击。
- 厂区/部门负责人、维修/保养人员只能看到授权厂区数据。
- 管理层和系统管理员可查看集团范围数据。

### 10.4 布局

- 页面没有整体横向滚动条。
- 内容区只有一个纵向滚动条。
- 表格横向滚动只出现在列宽超出容器时。
- 操作栏按钮保持单行。
- 图表、表格、筛选区在桌面和窄屏下不互相遮挡。

### 10.5 工程质量

- 单文件不超过 ESLint 规定的 600 行。
- 关键逻辑保留中文注释，特别是 mock 写操作、跨表联动、权限过滤、审批状态流转。
- `npm run typecheck` 通过。
- `npm run lint` 通过。
- `npm run build` 通过。
